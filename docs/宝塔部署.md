# 在宝塔面板上部署

宝塔自带 Nginx，占着 80 和 443。所以**不要用项目里的 Caddy**——`docker-compose.yml` 默认已经只起应用容器、只监听 `127.0.0.1:8000`，反代和证书交给宝塔。

全程约 20 分钟。

---

## 0. 前置

- 域名已解析到这台服务器（A 记录）
- 安全组 / 防火墙放行 80、443
- 宝塔面板 7.x 以上

> **域名不是可选项。** 扫码要调摄像头，浏览器规定 `getUserMedia` 只在安全上下文（HTTPS）下可用。用 IP 访问拿不到证书，扫码功能就是废的。

---

## 1. 装 Docker

宝塔面板 → **软件商店** → 搜索「Docker管理器」→ 安装。

装完在 **终端** 里确认：

```bash
docker -v
docker compose version
```

`docker compose version` 报错说明是老版本 compose，用 `docker-compose`（带横杠）替代下面所有命令即可。

---

## 2. 拉代码

宝塔 → **终端**：

```bash
mkdir -p /www/wwwroot && cd /www/wwwroot
git clone <仓库地址> snipe-panel
cd snipe-panel
```

没配 Git 的话，也可以在本地打包上传：宝塔 → **文件** → 进入 `/www/wwwroot` → 上传 zip → 右键解压。

---

## 3. 写 .env

```bash
cd /www/wwwroot/snipe-panel
cp .env.example .env
openssl rand -base64 48        # 复制这串输出
vi .env
```

必须填三项：

```ini
SNIPE_SECRET_KEY=刚才生成的那串
SNIPE_INITIAL_ADMIN_USERNAME=admin
SNIPE_INITIAL_ADMIN_PASSWORD=你自己定一个初始密码
```

`SNIPE_PORT` 默认 8000，被占了就改成别的（比如 8010），第 5 步反代要填一致。

> `SNIPE_SECRET_KEY` 泄露 = 任何人都能伪造登录态。别用示例值，别提交进仓库。
>
> `SNIPE_COOKIE_SECURE` 保持默认的 `true`。它让登录 Cookie 只在 HTTPS 下发送——第 5 步配完证书就正常了。**如果先用 http 测试会登不上（Cookie 被浏览器丢弃），这是预期行为，不要为此改成 false。**

---

## 4. 起服务

**国内服务器一定要先在 `.env` 里填镜像源**，否则 pip 拉包会超时：

```ini
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
NPM_REGISTRY=https://registry.npmmirror.com
```

> 不填的话构建会报 `Could not find a version that satisfies the requirement
> pydantic-core==... (from versions: none)`。**这不是版本冲突**，是索引请求根本
> 没拿到数据——看着像要去改版本号，方向全错。

```bash
cd /www/wwwroot/snipe-panel
docker compose up -d --build
```

第一次构建要几分钟（装 Python 依赖 + 构建前端）。完成后验证：

```bash
docker compose ps                          # 状态应为 running
curl http://127.0.0.1:8000/api/health      # 应返回 {"ok":true}
docker compose logs app | tail -20         # 应有「已创建初始管理员 admin」
```

`curl` 通了就说明应用没问题，剩下的都是反代的事。

---

## 5. 建站点 + 反向代理 + HTTPS

**5.1 建站点**

宝塔 → **网站** → **添加站点**：

- 域名：填你的域名，比如 `assets.example.com`
- PHP 版本：**纯静态**
- 数据库：**不创建**

**5.2 申请证书**

点站点名 → **SSL** → **Let's Encrypt** → 勾选域名 → **申请**。

签发成功后**打开「强制 HTTPS」**。

> 这一步必须先做。先配反代再签证书的话，验证请求会被转发给应用容器，导致签发失败。

**5.3 配反向代理**

点站点名 → **反向代理** → **添加反向代理**：

| 字段 | 填 |
|---|---|
| 代理名称 | snipe |
| 目标 URL | `http://127.0.0.1:8000` |
| 发送域名 | `$host` |

保存后点该条目的 **配置文件**，确认 `location /` 里有这几行，没有就补上：

```nginx
proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
```

> **`X-Forwarded-For` 这行不能少。** 少了的话应用看到的每个请求都来自 `127.0.0.1`，登录失败的 IP 限流会把全公司算成同一个来源——一个人输错几次密码，所有人都被限流。

顺便把上传和超时放宽（同一个配置文件里，`location /` 内）：

```nginx
client_max_body_size 20m;
proxy_read_timeout 300s;
```

保存 → 宝塔会自动 reload Nginx。

**5.4 验证**

浏览器打开 `https://assets.example.com`，应该看到登录页。用第 3 步设的 admin 账号密码登录，会被要求改密。

---

## 6. 上线前必须做的两件事

**6.1 改掉初始密码**

第一次登录系统就会强制你改。改完把 `.env` 里的 `SNIPE_INITIAL_ADMIN_PASSWORD` 也清空或改掉——它只在数据库为空时用得上，但留着是个隐患。

**6.2 配自动备份**

数据全在一个 SQLite 文件里，备份就是拷一个文件。宝塔 → **计划任务** → 添加：

- 任务类型：**Shell脚本**
- 任务名称：`snipe-panel 备份`
- 执行周期：每天 3:00

脚本：

```bash
#!/bin/bash
set -e
BACKUP_DIR=/www/backup/snipe-panel
mkdir -p $BACKUP_DIR
cd /www/wwwroot/snipe-panel

# 用 sqlite3 .backup 而不是直接 cp:WAL 模式下直接拷文件可能拿到不一致的快照
docker compose exec -T app python -c "
import sqlite3, pathlib
pathlib.Path('/data/backups').mkdir(exist_ok=True)
src = sqlite3.connect('/data/snipe.db')
dst = sqlite3.connect('/data/backups/latest.db')
src.backup(dst)
dst.close(); src.close()
"
docker compose cp app:/data/backups/latest.db $BACKUP_DIR/snipe-$(date +%F).db

# 只留最近 30 天
find $BACKUP_DIR -name 'snipe-*.db' -mtime +30 -delete
```

> 别用 `cp /data/snipe.db`。库开着 WAL 模式，直接拷文件可能拿到不一致的快照，恢复时才发现坏了。

## 日常操作

```bash
cd /www/wwwroot/snipe-panel

docker compose logs -f app        # 看日志
docker compose restart app        # 重启
docker compose down               # 停止(数据在 volume 里,不会丢)

# 更新代码后重新部署
git pull
docker compose up -d --build
```

**数据在哪**：Docker volume `snipe-panel_snipe-data`，不在项目目录里。`docker compose down` 甚至 `docker compose down --rmi all` 都不会删它。

> **`docker compose down -v` 会连数据一起删。** 别加 `-v`。

## 出问题时按这个顺序查

**打开是 502**

```bash
curl http://127.0.0.1:8000/api/health
```

- 不通 → 应用没起来，看 `docker compose logs app`
- 通了 → 反代配错了，检查目标 URL 的端口是否和 `.env` 里的 `SNIPE_PORT` 一致

**能打开但登录后立刻跳回登录页**

Cookie 没存下。多半是没开「强制 HTTPS」，或者还在用 http 访问——`SNIPE_COOKIE_SECURE=true` 时登录 Cookie 只在 HTTPS 下才会被浏览器保存。确认地址栏是 `https://`。

**手机能打开但扫码按钮点了没反应 / 提示无法调用摄像头**

- 确认是 `https://` 而不是 `http://`
- 确认证书有效（浏览器地址栏没有警告）
- iOS 上先在 Safari 普通标签页里试，再试「添加到主屏幕」——两种模式的摄像头行为历史上不一致
- 实在不行用页面上的**手动输入编号**，功能不受影响

**构建失败，报 `Could not find a version ... (from versions: none)`**

不是版本冲突，是连不上 PyPI。在 `.env` 里填 `PIP_INDEX_URL`（见第 4 步），再重建：

```bash
docker compose build --no-cache app && docker compose up -d
```

**代码明明推上去了，行为却没变**

先确认构建到底成没成——**Docker 构建失败时不会替换正在运行的容器**，旧容器会带着旧代码继续跑，日志看起来就像新代码没生效：

```bash
docker compose build app && echo "构建成功"
```

**改了代码但页面没变**

前端是构建进镜像的，必须重新 build：

```bash
docker compose up -d --build
```

**忘记管理员密码**

```bash
cd /www/wwwroot/snipe-panel
docker compose exec app python -c "
from app.db import SessionLocal
from app.models import User
from app.security import hash_password
db = SessionLocal()
u = db.query(User).filter(User.username=='admin').first()
u.password_hash = hash_password('TempPass12345')
u.must_change_password = True
u.failed_attempts = 0
u.locked_until = None
db.commit()
print('已重置为 TempPass12345,登录后会要求修改')
"
```

## 不想用 Docker 的话

宝塔的「Python项目管理器」也能跑，但要多做几步：装 Python 3.12、手动 `npm run build` 前端、配置启动命令加 `--proxy-headers --forwarded-allow-ips=*`、自己管进程守护。

**不推荐**。Docker 那条路把 Python 版本、依赖、前端构建都固定住了，出问题的面小得多。宝塔的 Docker 管理器装一下就有。
